# Nero의 Kafka 학습 계획

- 학습자: Nero / [zosungwoo](https://github.com/zosungwoo)
- 기간: 2026년 10월 2일 ~ 12월 31일, 13주
- 주교재: 고승범, **『실전 카프카 개발부터 운영까지』**, 책만, 2021
- 목표: 백엔드 개발자로서 Kafka의 구조와 전달 보장을 이해하고, 순서·중복·재처리·리밸런싱을 코드와 실험 결과로 설명할 수 있다.
- 범위: 3~6장을 중심으로 학습한다. 클러스터 운영 전문가 수준의 구축·튜닝은 목표에 포함하지 않는다.

## 진행 방식과 시간

주 4시간, 총 52시간을 기준으로 한다. 우선 **개인 학습 3시간 + 스터디 모임 1시간**으로 배분하며, 모임을 별도로 계산하는 경우 추가 시간은 실습과 복습에 사용한다.

- 읽기 90분: 해당 주차의 핵심 절을 읽고 개념과 질문을 정리한다.
- 실습 60분: 한 가지 동작을 예상하고 실행한 뒤, 결과와 이유를 비교한다.
- 발표 준비 30분: 핵심 질문 하나를 중심으로 짧은 Markdown 발표자료를 만든다.
- 스터디 60분: 주간 내용을 공유하고 질문을 논의한다. 각자 발표 길이는 운영 방식에 맞춘다.

아래 날짜는 **학습 기간**이다. 금요일 모임에서는 직전까지 학습한 내용을 공유하며, 10/2 첫 모임에서는 목표와 계획을 공유한다. 10/9·12/25 공휴일의 모임 개최 여부는 운영자와 협의한다. 마지막 주 결과는 12/31까지 레포에 정리한다.

## 교재와 실습 환경

책의 기준 환경은 Kafka 2.6, ZooKeeper 3.5.9, Java 8이다. 개념 설명과 버전별 구현·기본 설정값을 구분해서 기록한다.

1. 기본 실습은 로컬 컨테이너 환경으로 진행한다. AWS 계정이나 유료 클러스터를 필수로 사용하지 않는다.
2. 책의 동작을 재현하는 실습은 가능한 한 책의 버전에 맞춘다. 클라이언트·브로커·이미지 버전과 설정값을 기록하고, 최신 버전을 섞어 결과를 일반화하지 않는다.
3. 구버전 이미지가 로컬 환경에서 실행되지 않으면 환경 복구에 학습 시간을 모두 쓰지 않는다. 1주차에 실행 가능한 버전을 고정하고, 책과 다른 부분을 기록한다. 버전 의존적인 실습은 로그·예제 코드 분석으로 대체한다.
4. 복제·리더 장애 실습에는 다중 브로커가 필요하다. 단일 브로커로 복제 내구성을 검증했다고 결론 내리지 않는다.
5. KRaft는 12주차에 별도 환경으로 비교한다. 책의 ZooKeeper 기반 컨트롤러·업그레이드 절차를 현재 버전에 그대로 적용하지 않는다.
6. 공개 레포에는 직접 작성한 요약·실험 결과·예제 코드를 올린다. 회사 코드·내부 정보와 책 본문·도표의 대량 복제는 포함하지 않는다.

### 2주차 · 10/9–10/15 — 기본 구조와 Java 클라이언트

- **발표:** 파티션 내 순서 보장과 토픽 전체 순서 보장의 차이, 그룹별 독립 소비.
- **완료 기준:** 토픽·파티션·오프셋의 관계와 컨슈머 수를 늘릴 때의 제약을 설명한다.

### 3주차 · 10/16–10/22 — 복제와 장애 복구

- **읽기:** 4.1.1~4.1.5 리플리케이션 개요·리더/팔로워·복제 유지와 커밋·단계별 동작·리더 에포크와 복구 / 4.2 컨트롤러.
- **핵심 질문:** 브로커 장애가 나도 메시지가 남는 조건은 무엇인가?
- **실습:** 다중 브로커·복제 토픽에서 리더 브로커를 종료하고 리더·ISR·생산/소비 변화를 관찰한다. 실패 전후 설정과 로그를 남긴다.
- **발표:** 리더·팔로워·ISR의 역할, `acks`와 `min.insync.replicas`에 따른 성공/실패 조건.
- **완료 기준:** 복제 관련 커밋과 컨슈머 오프셋 커밋을 구분하고, `acks=all`만으로 모든 유실을 막는다고 설명하지 않는다.

### 4주차 · 10/23–10/29 — 로그 보관, 파티셔닝과 배치

- **읽기:** 4.3.1 로그 세그먼트 삭제, 4.3.2 컴팩션 / 5.1.1 라운드 로빈, 5.1.2 스티키 파티셔닝 / 5.2 Producer 배치.
- **핵심 질문:** 메시지 보관 방식과 전송 배치가 저장량·지연·처리량에 어떤 영향을 주는가?
- **실습:** 같은 키의 갱신 이벤트를 보내고 `delete`와 `compact` 정책의 차이를 정리한다. 시간이 남으면 배치 설정 하나를 바꿔 전송 결과를 비교한다.
- **발표:** 일반 압축과 로그 컴팩션의 차이, 처리량과 지연의 절충.
- **완료 기준:** 컴팩션이 비동기로 일어나며 즉시 키당 한 건만 남는 것은 아니라는 점을 설명한다.

### 5주차 · 10/30–11/5 — 멱등성과 트랜잭션

- **읽기:** 5.3 중복 없는 전송 / 5.4.1~5.4.4 정확히 한 번 전송의 디자인·예제·단계별 동작·실습.
- **핵심 질문:** Producer 멱등성과 트랜잭션은 각각 어떤 중복과 부분 실패를 다루는가?
- **실습:** 트랜잭션 Producer로 커밋/중단을 각각 실행하고 소비 결과를 비교한다. 브로커·클라이언트 버전, 멱등성 설정, Consumer 격리 수준을 기록한다.
- **발표:** 전송 재시도 중복과 애플리케이션이 같은 이벤트를 두 번 발행하는 중복의 차이.
- **완료 기준:** Kafka의 보장 범위를 외부 DB 갱신·HTTP 호출까지 자동으로 확장해서 설명하지 않는다. Consumer 측 처리는 7주차에 연결한다.

### 6주차 · 11/6–11/12 — 오프셋과 컨슈머 그룹

- **읽기:** 6.1 오프셋 관리 / 6.2 그룹 코디네이터 / 6.3 스태틱 멤버십. 필요하면 3.4의 컨슈머 옵션을 다시 읽는다.
- **핵심 질문:** 업무 처리와 오프셋 커밋의 순서에 따라 재시작 후 무엇이 달라지는가?
- **실습:** 수동 커밋 예제에서 처리 후 커밋 전에 종료해 재처리를 확인한다. 반대로 커밋 후 처리 전에 종료하면 해당 그룹에서 처리가 누락될 수 있음을 비교한다.
- **발표:** 소비 위치와 커밋된 오프셋, at-most-once와 at-least-once의 관계.
- **완료 기준:** 중복 처리와 처리 누락이 발생하는 시점을 설명하고, 이것을 브로커의 메시지 삭제와 구분한다.

### 7주차 · 11/13–11/19 — 파티션 할당과 리밸런싱

- **읽기:** 6.4.1~6.4.4 레인지·라운드 로빈·스티키·협력적 스티키 전략 / 6.5 정확히 한 번 컨슈머 동작.
- **핵심 질문:** 컨슈머 증감·재시작 시 파티션 소유권은 어떻게 바뀌고, 중복 처리는 어디서 방어해야 하는가?
- **실습:** 컨슈머를 추가·종료하며 할당 변화를 기록한다. 기본 전략과 협력적 스티키 전략을 비교하고, 5주차 트랜잭션 예제를 `read_committed` 소비와 연결한다.
- **발표:** eager/cooperative 리밸런싱의 차이, 스태틱 멤버십의 목적과 한계.
- **완료 기준:** 책의 그룹 프로토콜 기준으로 설명하고, 리밸런싱 방식을 최신 버전 전체에 일반화하지 않는다.

### 8주차 · 11/20–11/26 — 운영 지표와 확장의 의미

- **읽기:** 7.1 안정적인 구성, 7.2.1~7.2.3 로그·JMX·익스포터 / 8.1 업그레이드 준비, 8.2.4 주의사항, 8.3 확장·분산 배치. 8.2의 상세 업그레이드 명령은 참고용으로 읽는다.

- **실습:** 컨슈머 처리에 지연을 넣어 lag 증가·회복을 관찰한다. CLI로 확인하고, 전체 모니터링 스택 구축은 선택으로 둔다.
- **발표:** lag, 처리 속도, ISR 관련 지표의 의미와 병목 조사 순서.

### 9주차 · 11/27–12/3 — 보안과 애플리케이션 책임

- **읽기:** 9.1 암호화·인증·권한의 세 요소 / 9.2 SSL, 9.3 SASL, 9.4 ACL의 목적과 흐름. 인증서·커버로스 설치 명령은 정독 대상에서 제외한다.
- **핵심 질문:** 전송 암호화, 클라이언트 식별, 토픽 접근 권한은 각각 무엇을 보장하는가?
- **실습:** 6주차 재처리 예제에 이벤트 ID 기반 중복 방어를 추가하고 같은 이벤트를 두 번 처리해 결과를 확인한다. 이는 책의 개념을 응용한 개인 실습이다.
- **발표:** 보안 세 요소와, Kafka 전달 보장과 별도로 애플리케이션이 책임져야 하는 중복 처리.
- **완료 기준:** SSL·SASL·ACL을 구분한다. 메모리 기반 중복 방어를 썼다면 재시작·동시성 한계를 기록한다.

### 10주차 · 12/4–12/10 — 스키마와 호환성

- **읽기:** 10.1 스키마 / 10.2 Kafka와 Schema Registry·Avro / 10.3 클라이언트 동작 / 10.4.1~10.4.4 BACKWARD·FORWARD·FULL 호환성과 실습.
- **핵심 질문:** Producer와 Consumer를 동시에 배포하지 않고 메시지 형식을 바꿀 수 있는가?
- **실습:** 작은 Avro 스키마에서 기본값 있는 필드 추가와 타입 변경을 비교한다. 가능하면 Registry의 호환성 검사를 실행하고, 어렵다면 읽기/쓰기 스키마 조합을 표로 검증한다.
- **발표:** 새 Consumer가 과거 데이터를 읽는 경우와 옛 Consumer가 새 데이터를 읽는 경우의 차이.
- **완료 기준:** 호환성 방향을 암기 대신 배포·재처리 시나리오로 설명한다. 책의 Python 예제는 흐름 이해에 활용한다.

### 11주차 · 12/11–12/17 — Kafka Connect와 데이터 연동

- **읽기:** 11.1 핵심 개념 / 11.2 내부 동작 / 11.3 파일 Source·Sink / 11.4 분산 모드 / 11.5 MirrorMaker 2.0 개요.
- **핵심 질문:** 직접 Producer/Consumer를 작성하는 대신 Connector를 쓰면 무엇이 달라지는가?
- **실습:** 간단한 파일 Source → Kafka → 파일 Sink 흐름을 한 번 구성하고, 재시작 후 처리 위치를 확인한다. 커넥터와 런타임 버전을 기록한다.
- **발표:** worker·connector·task의 역할, 직접 개발과 Connect 사용의 선택 기준.
- **완료 기준:** 소스/싱크를 구분하고, Connect를 쓰는 것만으로 모든 외부 시스템에 exactly-once가 보장되지는 않음을 설명한다. 다중 클러스터 미러링은 개념만 다룬다.

### 12주차 · 12/18–12/24 — 전체 아키텍처와 현재 Kafka의 차이

- **읽기:** 12.1 엔터프라이즈 아키텍처 개요, 12.2~12.3 구성·운영 흐름 / 13.1~13.4 ZooKeeper 제거 배경·합의 프로토콜·컨트롤러·KIP. 부록 A의 관리형 서비스는 비교 관점으로 훑는다.
- **핵심 질문:** 책의 구조에서 현재 Kafka로 바뀐 부분과 여전히 유지되는 개념은 무엇인가?
- **실습:** 별도 로컬 KRaft 환경에서 기본 메시지 송수신을 확인한다. 공식 문서로 컨트롤러 구성과 그룹 프로토콜 변경 등 책과 다른 부분을 확인한다.
